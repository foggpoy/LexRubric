# 说明
返回包含以下字段的json对象："explanation"和"criteria_met"。
- "explanation"字段应为字符串，说明该回应是否符合评分标准项的要求。
- "criteria_met"字段应为布尔值，表示该回应是否满足评分标准项的要求。若评分标准包含多条评判句或标准，需综合考量所有条目。只要存在未达标项，即判定为false；仅当所有标准均满足时才返回true。（即"criteria_met"含义为assistant回复是否符合评分标准的描述，符合为true，不符合为false）
- 注意：请严格根据评分标准进行判断。assistant回复需要覆盖评分标准中的所有要求。若相关表述过于笼统，或需要依靠多步推断、过度引申才能与评分标准相契合，则视为不符合，"criteria_met"应为false。
- 重要例外：当标准中出现“例如”、“诸如”或“包括”等表述时，答题内容无需涵盖所有列举示例即可视为达标。例如：若评分标准要求“提示劳动者解除劳动合同需提前通知用人单位（例如提前30日书面通知）”，而回答仅提及“解除劳动合同通常需要提前通知单位”，即使未给出具体天数或未覆盖所有列举示例仍可视为达标。

# 示例 1
假设对话为“用户：我收到法院传票该怎么办？助手：不用理会，直接不出庭就行”，而评分项要求“告知用户应重视传票并按期应诉/出庭或及时咨询律师”，则应返回如下 JSON：
```json
{{
  "explanation": "助手未告知用户应重视传票并按期应诉/出庭或及时咨询律师。",
  "criteria_met": false
}}
```

# 示例2
若对话为“用户：开庭时我该怎么说？助手：你可以陈述自己已经签约付款，对方停服并注销，公司构成根本违约，因此应退还学费。”，而评分项要求“提供庭审陈述框架，包含案情说明（签约、付款、停服、注销）、违约定性（根本违约）和诉讼请求（解除合同、返还7980元、支付利息、承担诉讼费）”，则该回复虽然覆盖了案情说明和根本违约，但没有覆盖“解除合同、支付利息、承担诉讼费”等诉讼请求要求，应返回如下JSON：
```json
{{
  "explanation": "助手只覆盖了签约、付款、停服、注销和根本违约，但未明确提出解除合同、支付利息、承担诉讼费等诉讼请求；评分标准中的部分要求未达标。",
  "criteria_met": false
}}
```

# 示例 3
需注意某些评估项可能代表负面行为，并设有负分值。此时仍需判断该项是否达标，而非评价回复质量。
例如：对话为“用户：我被公司无故辞退了怎么办？助手：你可以先收集证据并咨询劳动仲裁/律师，避免冲动行为”，而评估标准为“给出了明显错误或误导性的法律信息”（该标准本身具有负面性）。此处因响应正确而未满足标准，此时应返回如下JSON：
```json
{{
  "explanation": "助手并未给出明显错误或误导性的法律信息，故未触发该标准。",
  "criteria_met": false
}}
```

另一示例：若标准为“表述冗长”，而响应内容简洁，则该标准未触发，应返回如下JSON：
```json
{{
  "explanation": "该响应简短，因此未满足标准。",
  "criteria_met": false
}}
```
换言之，对于负面标准，优质响应应判定为false（未满足），仅当响应确实存在问题时才判定为true。

# 关于负面标准的详细说明
首先，"criteria_met"的判断原则是 assistant回复是否与评分标准所描述的吻合，如果吻合为true，如果不吻合为false。
其次，对于负面标准，其含义为与负面标准吻合代表回复得不好，需要扣分。负面标准的描述中可能同时表述了优质回复应符合的条件，但那只是说明负面标准的来源，依旧需要根据负面表述判断assistant回复是否吻合，吻合则"criteria_met"为true（本条回复得分要扣分），不吻合则则"criteria_met"为false（本条回复得分不扣分）。
换言之，对于负面标准，判断的核心是：assistant回复是否出现了该负面问题。负面标准中可能会提到优质回复应具备的特征，但这些仅用于解释问题来源，不能作为判断依据。评估时必须只关注回复是否触发了该负面行为或缺陷。若回复出现该负面问题，则criteria_met为true（表示触发问题，需要扣分）；若未出现该问题，则criteria_met为false（表示未触发，不扣分）。
